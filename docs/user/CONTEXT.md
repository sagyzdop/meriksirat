# docs/user/ — how-to guides for humans

One job: explain how to use the platform, in the language of someone using it — not building it.

## Inputs

- Reference (every run): the feature's behavior in `../../src/` when steps are in doubt.
- Reference (every run): sibling guides here — booking flow is the spine the others hang off.

Do NOT load: `../dev/` (implementation detail does not belong in these guides).

## Process

1. Describe steps as the user sees them in the app or Telegram bot.
2. One home per fact: cross-link guides instead of repeating a workflow.

## Outputs

- Updated guide in this folder, registered in `README.md` → Documentation.

## Human check

Walk the described steps in the app (or bot) once — each button/label matches reality.
